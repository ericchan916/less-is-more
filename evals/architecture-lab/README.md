# 接受回执与副作用恢复

这是作者构造的隔离候选回归，不是线上服务，也不比较 Agent 的判断质量

## 固定契约

- 同一租户和请求键代表同一意图，换内容必须拒绝
- 接受过的请求在本实验期间不清理，重新实例化可恢复
- 远端已接受、本地尚未确认时中断，恢复不能盲目重复副作用
- 本地未知不能伪装成成功；缺少恢复协议时保留不确定状态

模拟 Provider 只在十个模拟秒内按 operation id 去重；另可配置一个不随此窗口过期、强一致且能明确返回不存在的查询能力。真实服务若只有最终一致查询、不确定错误或不同保留期，不能直接套用该假设

## 候选与运行

```sh
python3 -B evals/architecture-lab/probe.py
```

| 候选 | 路径 | 判断 |
| --- | --- | --- |
| 原分层 | Intake → Forwarder → AcceptanceOwner → Provider | 转发层没有额外契约，保留作为行为基线 |
| 完整精简 | AcceptanceOwner → Provider | 去掉纯转发，保留本地意图与远端确认职责 |
| 表面更短 | BlindRetry → Provider | 本地状态更少，但回执丢失后在窗口外重复接受 |

十个测试方法覆盖正常重试/重开、租户、冲突、中断窗口与恢复。无查询时，原幂等窗口仍有效可安全重试；重试不延长该窗口，到期后不能盲目重发。坏候选产生两条远端记录是预期的反例观察，不代表它通过业务契约；没有查询时的暂停也不代表自动完成。部分测试对基线和精简候选分别运行，测试方法数不等于不同故障条件数

实现只使用标准库、临时目录与模拟时间，没有网络、账户、真实资金或生产数据。它验证逻辑中断点后的重新实例化，不验证真实断电、并发竞争、外部查询一致性、鉴权或生产可用性；不根据减少层数推算提速或费用
