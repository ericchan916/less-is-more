# 单次隔离对照 预先固定方案

日期 2026-10-26，用户授权两名执行 Agent 及一名后续只读复核 Agent，继承当前模型与强度。本样例此前未交给 Agent 执行，属于作者构造的新合成场景；不是随机行业样本

两份相同 seed 代码和 README。随机将一份分配到使用当前 less-but-better 冻结稿，另一份仅使用常规能力。执行 Agent 不获知预期答案、隐藏验收或另一侧结果，禁止读取副本外文件、联网及额外委派。文件系统没有硬隔离，隔离依靠范围约束与后续工具记录核查，不能称严格实验室盲测

## 先看契约 再看收益

1. 冻结 `evaluator/contracts.py` 的公开行为验收：输入/返回/权限、合法选项组合、改价一致性、草稿与确认订单的独立持久性、旧数据读取和引用隔离。seed 必须先通过。不能为某个候选改变验收
2. 对两侧分别运行相同验收；任一必要功能回退都不能算成功精简
3. 按实际代码核查报价公式的规则拥有者、派生报价的持久写入与同步触点、必要业务事实承担者。较少类、文件、行数仅描述实现，不单独计胜负
4. 比较两侧为同一规则更改需要触及的位置及恢复/迁移负担。若功能与净结构结果相同，报告本案例没有架构增益，不用输出更短代替架构收益
5. 最后核对 RESULT.md 是否简洁准确。两侧报告都限 180 个中文字，不因冗长报告反推架构更好

独立复核者先看匿名 A/B 成品与冻结验收，记录功能和结构结论后再读取分组映射。随后读取真实发布 diff、素材/许可说明、检查记录，审查是否适合发布；本轮最多使用一个复核 Agent，不另启审查链

单次、同一模型、作者构造和非硬隔离均限制因果推论。结果不能证明不可替代、普遍优于常规 Agent、所有宿主兼容、生产可用或星标目标
