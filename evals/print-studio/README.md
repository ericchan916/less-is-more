# 印刷报价系统 单次对照

普通 Agent 与读取当前 skill 的 Agent 各处理一份相同的新合成案例。两边都通过预先固定的 18 项契约测试，都统一了两处报价规则，退役了派生报价的持久缓存和改价时的失效同步，保留了价格、可编辑草稿与已确认订单

**本案例没有观察到 skill 的额外架构收益**。类数和行数不同不改变这一判断，不以输出较短作为架构优势

| 观察 | 基线 | 普通 Agent | 使用 skill |
| --- | --- | --- | --- |
| 相同契约测试 | 18 通过 | 18 通过 | 18 通过 |
| 报价规则拥有者 | 2 | 1 | 1 |
| 派生报价持久缓存 | 有 | 无 | 无 |
| 改价时缓存失效调用 | 1 | 0 | 0 |
| 草稿与确认订单 | 独立保存 | 独立保存 | 独立保存 |

测试涉及权限、输入、选项组合、旧存储、重新打开、未提交草稿、确认订单快照与字典引用隔离。原始副本另有三项可见快速测试；固定验收中的组合方法检查了 48 组合法规格，方法数不等于全部条件数

## 重现

在此目录运行，仅使用 Python 标准库和临时合成数据

```sh
python3 -B contracts.py baseline
python3 -B contracts.py ordinary
python3 -B contracts.py skill
```

[冻结方案原文](PROTOCOL.md) · [冻结摘要与分组](FROZEN.json) · [实际指标与代码哈希](results.json) · [匿名独立复核](independent-comparison-review.md)

方案原文中的 seed、A、B 和 evaluator 是原试验目录名称；发布目录将 seed 映射为 baseline，A 映射为 skill，B 映射为 ordinary。候选源码与执行者 RESULT.md 原样保留，其中额外测试数字为自报，未独立核实，未作为组间指标，扩展脚本未随包提供

## 边界

单案例由 skill 作者构造，使用相同父级模型与强度配置，不代表其他模型或行业。执行者通过范围约束分开，文件系统没有硬隔离，全部工具记录未获独立审计。匿名复核者先看代码与验收，后获分组；具体复核状态记录在 results.json

这不是视觉审美对照，也不验证并发、磁盘故障、损坏数据或生产支付。结果不能证明普遍优于普通 Agent、所有宿主兼容、百分百有效或不可替代
