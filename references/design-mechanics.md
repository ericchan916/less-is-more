# 从审美目标到实现决定

以下数值是可调整的起点，不是 Apple 官方规范，也不是所有网页的及格线。优先适配现有品牌、真实内容、设备和用户任务。

## 先做文案减法

整页辅助文案最多两块，优先不用。它包括装饰性眉题、角标、编号、解释段、英文点缀与页脚口号；不是只数某个 CSS 字号，也不是每屏重置。必要的操作标签、真实业务内容与反馈不纳入装饰预算，但仍检查重复。别把说明改成大号字或塞进折叠区来规避规则。

| 原表达 | 决定 | 结果 |
| --- | --- | --- |
| 声音有形。生活，从容。 | 换成产品与特征 | AURA One / 桌面好声音，以换行分开 |
| 为日常，留一点好声音。也为每个空间，留一点余地。 | 主图与标题已表达，删除 | 无辅助段落 |
| 图片两角的编号、材质短语；图下两条口号 | 去掉重复注解 | 让产品本身成为视觉主体 |
| 为思考，腾出一点空间。 | 主体直接用短词组 | 整理思路 |
| 本地规则体验、不上传内容的说明 | 保留必要事实，集中一处 | 内容仅存此浏览器 / 本地规则整理 无在线模型 |

这里的斜线只表示示例中的换行，不要求成品输出斜线。中文标题和卖点默认无逗号、句号等装饰性标点；正文需要准确表达时正常使用。用户的文稿、引文与金额时间不改写。短词组仍须说清产品，不用含糊口号替代信息。

## 三类页面，三种注意力分配

| 类型 | 主体与构图 | 如何体现精致 | 常见误用 |
| --- | --- | --- | --- |
| 产品、空间、品牌 | 有明确焦点的产品/场景影像；文字与主体轮廓形成关系 | 真实材质、光向、尺度、精确裁切；叙事逐层揭示细节 | 小产品缩在卡片中，周围填满空泛卖点；低质图叠上玻璃光效 |
| 软件营销、创作入口 | 一句清楚主张，接产品使用情境或可操作样例 | 文案、界面、示例数据共同证明产品；视觉焦点能转成真实操作 | 装饰性控制台、假统计、虚构客户标志、不能操作的按钮 |
| 工作台、编辑器、业务系统 | 用户当前内容/数据与下一步操作 | 对齐、阅读宽度、稳定状态、紧凑而清楚的工具层；空间用于区分职责 | 把营销页大标题移到首屏；隐藏常用操作来降低按钮数 |

## 六项设计约定

用少量具体决定约束后续实现；下面是示例而不是必套版式。

- **任务**：了解一款音响并预约体验；不是直接交易。
- **主体**：一张能看清金属网孔、接缝与旋钮的原创产品图。
- **构图**：暖灰画布，标题与影像形成纵向主轴；导航窄，主体大。
- **字体/颜色**：系统无衬线配少量衬线或统一无衬线；墨色为内容，暖橙只用于品牌细节与主操作。
- **文案预算与节奏**：辅助文案至多两块；首屏整体 → 材质细节 → 必要规格与预约，去掉图片角标与重复解释。
- **交互**：预约在原页面内完成可撤销选择；导航直达内容；结果清楚反馈。

同样方法用于软件：主视觉可改为一份真实文稿，主动作改为整理，光效改为轻微层级；不用为了“有图”增加与任务无关的摄影。

## 比例与空间

- 营销页桌面容器可从约 1120–1360px 开始，外侧边距随视口变化；工作台按数据列数与任务调整。正文列一般比整体容器窄。
- 标题、说明、元信息形成明显尺度差。展示标题可从桌面 56–100px、手机 36–52px 试起；高频应用标题通常更小。避免所有正文都用浅灰小字。
- 大区块可从 80–140px 的纵向距离试起，手机明显收紧；相关标签与内容的距离远小于区块距离。禁止为满足数字硬凑空白。
- 用可见基线、边界和文字块宽度判断对齐，不只看盒子是否居中。标题换行要形成清楚语义；汉字慎用大幅负字距和超细字重。
- 让视口里的主体有足够尺度。背景图是否能看清主物、手机裁切是否丢失产品，比“用了高清图”更重要。

## 排版工整与布局美感

### 在实现前确定少量关系

先定整体容器、列关系、外边距、对齐轴和文字角色，再摆内容。将常用间距、字体尺度和控件高度设为少量 token；数值由真实内容决定，不把固定网格、黄金比例或某种列数当作高级感的证明。

- 横向检查标题、图片、正文和操作的起止边界；纵向检查同级基线、按钮中心和上下间距。不同对齐方式必须表达真实层级，避免每块独立随意摆放。
- 图像以主体轮廓、重心和裁切参与构图。透明边、照片留白和字形侧边会影响视觉对齐；必要时做少量有依据的光学校正，不用大量逐元素偏移掩盖网格问题。
- 字体按标题、正文、控件等职责使用；同类内容保持一致的字号、字重、行高和行长。展示标题按语义换行，避免单个汉字或一个短词被挤到末行；不要硬编码大量换行适配一张截图。
- 真实控件、内容和空白共同构成画面。主体应有足够尺度，次要元素退后；没有内容的卡片直接撤掉，不靠扩大空容器或补装饰文案维持版式。

### 用真实内容检查，逐个修可见问题

桌面和手机分别检查首屏、后续区块和关键状态。用原尺寸看边界、字形、换行、控件与图像边缘，再缩览整页看视觉重心和区块节奏。按需检查平板、长标题、长正文、字体回退和错误提示；不只看最短示例。

发现不齐，先查共用容器、字体度量、布局约束或 spacing token；发现失衡，先调整主体尺度、列关系和区块密度。不要为每处问题加一个独立 margin、额外卡片或说明。响应式保留关系并重新组织内容，不能通过隐藏必要功能或缩小到难以阅读解决。

交付前不能留有已发现且可修正的溢出、重叠、错位、孤字、空壳或无理由的间距漂移；有意的非对称构图与动态变化不机械判为错误。截图与尺寸检查可以证明观察与布局状态，不能证明“审美极致”或替代用户判断。

## 影像与素材路线

先复用用户提供且可用的素材；不足时选择已授权的素材来源或生成能力。商业品牌图只作研究，不默认下载后重新包装成自有产品图。真实商品不能用生成图虚构其结构、认证或功能；概念演示明确标识即可，不编造销量、性能或客户证言。

为需要生成的每张图写清：用途、主体、机位/主体位置、光线与材质、与页面背景的关系、手机裁切、禁止元素。文字与按钮由 HTML 实现，不烘焙进背景。软件界面优先真实 HTML，不让整页变成不可访问的截图。

示例素材约定：

> 原创概念音响的产品照片，三分之四前视；细腻金属与橡木，单个暖橙旋钮；浅暖灰影棚与自然接触阴影；主体周围保留裁切余量；无文字、logo、界面或水印。

生成后实际看图，再接入项目；检查边缘、结构合理性与桌面/手机裁切。将最终文件保存在项目内，设置图片尺寸、合适的加载优先级与替代文本。按宿主允许的方式压缩或提供响应式版本；不要为了搬运素材绕过访问限制或付费权限。

## 颜色、表面与运动

为背景、内容、弱信息、边界、强调与状态分配职责。强调色可以很鲜艳，但正文和控件仍须可读；不能靠品牌色单独传达成功、错误或选择。

表面层级先少后精：画布、内容、浮层各有明确意义。常驻页面不用满屏模糊。照片里的光向和阴影与 UI 材质协调；不要给每个区块都加发光边框。

反馈先即时，再考虑动画。hover/press 可从 120–220ms、面板变化从 220–420ms 试起；这些是本方法的工程起点。不要让用户等待文字出现才可读、等待动画才可操作；内容在脚本失败时仍应尽可能可用。支持 reduced-motion，避免无必要的持续运动和滚动劫持。

## 检查的是差异，不是装饰数量

截图先通看整页，逐块判断辅助文案是否必要与预算是否超出，再查“产品在手机仅剩旋钮”“必要文字过淡”等缺陷。优先删掉无用文字与容器，再调整主体、素材和移动端布局；不要先靠调圆角和放大说明补救。

技术检查覆盖资源加载、溢出、语义与关键操作；视觉检查关注构图、主体、层级、节奏和一致性。两者分别记录，不用一组技术测试冒充高级感评分。
